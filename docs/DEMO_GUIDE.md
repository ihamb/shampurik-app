# Как показать демо Shampurik

Демо — статический сайт без серверной базы, регистрации и приёма оплаты. Заведение «Мангал у дома» и все его показатели вымышлены. Реальных клиентов и подтверждённых продаж в демо нет.

## Запуск

Из корня репозитория:

```sh
npm run dev
```

Открыть `http://localhost:4173`. Нужны Node.js для команд npm и Python 3 для локального сервера; устанавливать npm-зависимости не требуется. Альтернатива: `python3 -m http.server 4173`.

Файл `index.html` следует открывать через HTTP-сервер: ES-модули при открытии через `file://` браузер может блокировать. Статические файлы можно разместить на GitHub Pages или другом статическом хостинге.

## Показ за пять минут

1. Сразу указать: кафе и цифры демонстрационные, это не результат существующего платного клиента.
2. Показать выручку, рост затрат на продукты и маржу после ингредиентов. Проговорить, какие расходы не учтены.
3. Выбрать блюдо с повышенной долей продуктов. Сопоставить стоимость ингредиентов, цену продажи и цену при выбранной целевой доле.
4. Изменить текущую закупочную цену одного ингредиента. Показать пересчёт отчёта и связанных блюд.
5. Подвинуть целевую долю затрат на продукты. Объяснить, что это настройка владельца, а не универсальная норма для любого кафе.
6. Показать экспорт CSV и «Сохранить PDF» — печать браузером, где можно выбрать PDF. Для PDF рекомендуется альбомная ориентация.
7. Открыть условия пилота. Переход к [@hambinst](https://t.me/hambinst) открывает Telegram, но сам ничего не отправляет. Оплаты и автосписаний в демо нет.

## Что считает отчёт

- Стоимость продуктов на порцию: сумма количества ингредиента × его закупочная цена.
- Выручка: цена блюда × продажи за выбранный период, суммарно по блюдам.
- Маржа после ингредиентов: выручка минус текущая стоимость продуктов для этих продаж.
- Изменение затрат: текущая стоимость продуктов минус стоимость по прежним закупочным ценам **при том же количестве продаж**.
- Доля продуктов: текущая себестоимость ингредиентов ÷ цена продажи × 100%.
- Цена при цели: себестоимость ингредиентов ÷ целевая доля, округлённая вверх до 10 ₽.

Рецептура должна содержать количество уже с учётом применимых потерь и выхода. Единица количества соответствует единице закупочной цены: например, `0.25` при цене за кг означает 250 г. Самостоятельно отходы, усушку и выход демо не определяет.

Внутренний показатель `projectedRecovery` — сценарный прирост выручки при повышении цен до расчётных и неизменном объёме продаж. Это не обещание прибыли: спрос, ассортимент, затраты и объём продаж могут измениться.

Цель по умолчанию — 35%. Сигналы в таблице: выше 45% — критический; выше выбранной цели — внимание; иначе — в пределах цели. Это правила демонстрации, а не отраслевой норматив. Маржа не включает аренду, зарплаты, упаковку, налоги, комиссии доставки и другие расходы.

## Свои данные

Скачать пример JSON кнопкой в интерфейсе или взять [samples/mangal-demo.json](../samples/mangal-demo.json). Заменить значения, сохранив структуру:

```json
{
  "name": "Моё кафе",
  "period": "Октябрь 2026",
  "ingredients": [
    { "id": "meat", "name": "Мясо", "unit": "кг", "previousPrice": 400, "currentPrice": 450 }
  ],
  "dishes": [
    {
      "id": "kebab",
      "name": "Шашлык",
      "category": "Мангал",
      "price": 400,
      "sales": 100,
      "recipe": [{ "ingredientId": "meat", "quantity": 0.25 }]
    }
  ]
}
```

`id` должны быть уникальными, с латинскими буквами, цифрами, `_` или `-`. Цена продажи строго больше нуля; цены ингредиентов и количества неотрицательны; продажи — целое неотрицательное число. Рецепты ссылаются на существующие ингредиенты. Поддерживается до 200 ингредиентов и 100 блюд; недопустимые данные отклоняются с пояснением.

Импорт — только JSON. Импорта Excel/CSV и синхронизации с кассой в этой версии нет. Данные обрабатываются в браузере, не отправляются на сервер и не сохраняются после перезагрузки. Для клиентских таблиц использовать согласованные данные без персональных сведений; не коммитить их в публичный репозиторий.

## Проверка расчётов

```sh
npm test
```

Расчётный модуль: `src/report.mjs`. Экспорты: `validateData(data)` возвращает список ошибок, `calculateReport(data, { targetFoodCost: 35 })` возвращает отчёт или выбрасывает ошибку валидации. Демонстрационный набор экспортируется как `sampleData` из `src/sample-data.mjs`.

Для перехода к клиентскому пилоту использовать [PILOT_PLAN.md](./PILOT_PLAN.md). Само наличие демо не подтверждает спрос или готовность клиентов платить.
